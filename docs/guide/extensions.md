# Расширения

VI умеет ставить браузерные расширения — из папки, `.zip`, `.crx` или `.xpi`.
**Настройки ▸ Расширения**

::: warning Прочитайте это до установки
У расширений здесь есть **измеренная граница**: content-скрипт на странице
запускается, но не может ни написать своему расширению, ни получить от него
сообщение. Расширение, чей content-скрипт самодостаточен (стиль, скрипт со
своими данными, что-то, что делает своё дело и никому не докладывает), работает.
Расширение, чей content-скрипт — клиент своего фонового процесса, а это
большинство, — не работает.

Диалог установки говорит это про **конкретное** расширение, ещё до того, как оно
запустится, и вердикт остаётся на строке в списке.
:::

## Что работает

| | |
|---|---|
| фоновая страница и service worker | запускается, `browser.*` на месте |
| `storage`, `alarms`, `cookies` | работают |
| `tabs.query`, `tabs.onUpdated` | работают: расширение видит колонки VI с их адресами и заголовками |
| content-скрипты из манифеста | **выполняются**, DOM доступен |
| динамически зарегистрированные скрипты | выполняются |
| `declarativeNetRequest` | **блокирует по-настоящему** — и подзапросы, и переходы |
| всплывающее окно расширения | работает, кнопка живёт в верхней строке |

## Что не работает

| | |
|---|---|
| `runtime.sendMessage` из content-скрипта | «Tab not found» |
| `tabs.sendMessage` в content-скрипт | молча ничего не доставляет |
| `scripting.executeScript`, `scripting.insertCSS` | не выполняются |
| `webRequest` | в WebKit его нет вообще |

Все отказы, кроме последнего, — один и тот же отказ, и он не про VI вообще, а про
то, каким способом здесь рисуются страницы.

## uBlock Origin Lite

Самый интересный случай: это MV3-блокировщик, у которого есть сборка ровно под
этот API. Он ставится, включает свои списки, не выдаёт ни одной ошибки — **и не
блокирует ничего**, потому что его логика решает по вкладке, а вкладку он здесь
не видит.

Поэтому [блокировка рекламы в VI своя](/blocking) и ни от каких расширений не
зависит. uBOL ставится и показывает свой вердикт, как любое другое расширение;
просто он не блокирует.

## Правила

- **Расширение принадлежит профилю**: своё хранилище, свой контроллер. Разные
  профили — разные расширения.
- **В приватном окне расширения не работают вовсе.** Приватный просмотр нигде не
  записывается, а хранилище расширения — это запись.
- **Разрешения** выдаются при установке, там же, где диалог их перечислил; всё,
  что расширение попросит позже, спрашивается отдельно.
- Установка или включение расширения пересобирает открытые страницы: страница,
  открытая до его появления, иначе никогда бы его не увидела.
- Расширения из App Store подключить нельзя: они принадлежат своим приложениям.
- Подпись `.crx` никто не проверяет — как и написано в диалоге установки: из
  того, что расширение откуда-то скачано, не следует ничего.
